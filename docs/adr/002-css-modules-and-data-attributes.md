# ADR-002: 스타일은 CSS Modules + `data-*` 속성으로 만든다

- 상태: 채택됨
- 날짜: 2026-10-29

## 배경

컴포넌트의 variant(`primary`, `danger`)와 size를 스타일에 연결하는 방법은 여러 가지입니다.
이 시스템은 런타임 비용 없이, 소비하는 앱의 번들러에 특별한 요구를 하지 않으며, 테스트와 DevTools에서 상태를 읽기 쉬워야 합니다.

## 결정

- 스타일은 **CSS Modules**로 작성하고, 라이브러리 빌드 시 하나의 `styles.css`로 내보냅니다. 클래스 이름은 `maru-Button__root__hash` 형태로 고정해 충돌을 피하고 디버깅을 쉽게 합니다.
- variant, size, 상태는 클래스 조합이 아니라 **`data-variant`, `data-size`, `data-loading` 속성**으로 표현하고, CSS는 `.root[data-variant='danger']`처럼 속성 선택자로 분기합니다.
- 분기 규칙은 요소의 속성을 직접 바꾸지 않고 **컴포넌트 지역 변수**(`--button-bg`, `--button-fg` 등)만 바꿉니다. 실제 스타일 규칙은 한 곳에만 있습니다.
- 값은 항상 토큰(`var(--maru-...)`)에서 가져옵니다. 하드코딩된 색상과 간격은 두지 않습니다.

## 검토한 대안

- **CSS-in-JS (styled-components, Emotion)**: 런타임 비용과 SSR 설정이 필요하고, RSC와의 호환 문제가 있습니다.
- **Tailwind + CVA**: 빠르지만 소비하는 앱도 같은 Tailwind 설정을 가져야 하고, 토큰 구조를 직접 설계한 것이 드러나지 않습니다.
- **Vanilla Extract / Panda CSS**: 타입 안전한 zero-runtime이라 유력한 대안입니다. 빌드 플러그인 요구가 생기므로 지금은 보류했고, 필요가 생기면 재검토합니다.
- **클래스 이름 조합 (`button--danger`)**: 동작은 같지만, 테스트에서 상태를 읽을 때 구현 세부(해시된 클래스명)에 의존하게 됩니다.

## 결과

- 테스트와 DevTools에서 `data-variant="danger"`처럼 **공개된 계약**으로 상태를 확인할 수 있고, 해시된 클래스명에 의존하지 않습니다.
- 소비하는 쪽은 `@ohseungik/maru-ui/styles.css` 한 줄만 불러오면 됩니다. 별도의 빌드 설정은 필요 없습니다.
- 컴포넌트 CSS는 `prefers-reduced-motion`과 `forced-colors`(Windows 고대비 모드)를 직접 다룹니다.
- 단점 1: 속성 선택자는 특이도가 `(0,2,0)`이라, 소비하는 쪽의 단일 클래스 스타일이 덮어쓰기에서 질 수 있습니다. 필요해지면 `@layer`를 도입해 라이브러리 스타일을 낮은 우선순위 레이어로 내보내는 방안을 검토합니다.
- 단점 2: 스타일 파일이 하나로 합쳐지므로, 쓰지 않는 컴포넌트의 CSS도 포함됩니다. 현재 규모에서는 무시할 수준이며, 컴포넌트가 늘면 번들 크기 리포트로 추적합니다.
